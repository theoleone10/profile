Paperboy

Your newsletters, turned into one short audio brief every morning.

By Theo Leone · Solo: app, backend, infra · 2025–26

You sign in with Google and choose which newsletters you want. At the time you set, Paperboy reads the latest issues and writes one script at the length you picked. It records the script in the voice you chose and sends a notification when your episode is ready. Gmail access is read-only, and only the newsletters you chose are ever read.

What I built

  • Gmail sync and parsing to find newsletters and pull out the readable text
  • A script pipeline on GPT-5 mini with per-segment word budgets, so episodes land on the length you picked
  • Inworld text-to-speech voiced section by section, so every chapter’s start time is exact
  • Security for App Store review: keychain JWT sessions, ownership checks, signed OAuth state, rate limits, in-app account deletion
  • A React Native player with chapters, transcript, archive, background audio and a Live Activity

export async function generateSectionedAudio(sections, voice, measure) {
  const perSection = await Promise.all(
    sections.map(async (text) => {
      const buffers = await Promise.all(
        chunkText(text).map((chunk) => generateAudio(chunk, voice))
      );
      const durations = await Promise.all(buffers.map(measure));
      const seconds = durations.reduce((sum, d) => sum + d, 0);
      return { buffers, seconds };
    })
  );
  const startSeconds = [];
  let elapsed = 0;

    startSeconds.push(Math.round(elapsed * 10) / 10);
    elapsed += section.seconds;
  }

    Waypass

    The whole cremation workflow, from intake to completion, on one platform.

    By Theo Leone · Multi-tenant SaaS · 2026

    Funeral homes still run cremations with phone calls and paper. Waypass connects them with crematoriums and shipping partners, follows each case from intake to completion, and gives families their own view of a case’s progress.

    What’s in it

    • Case pipeline covering intake, custody, documents and completion
    • Booking flow: the funeral home proposes times, the crematorium answers from a private emailed link, the home confirms
    • Every booking step written to an audit log of booking events
    • PostGIS search for nearby partners, shown on Google Maps
    • Family portal, financial dashboard, in-app inbox and Resend email
    • Workspaces with roles, and a Cmd+K palette that searches everything

    Kaeru

    Japanese grammar, a little every day.

    By Theo Leone · Solo: design, code, content · 2026

    Each JLPT level is a train line and each grammar point a stop: 421 of them, N5 to N1. Each day you learn a few points, take a quiz, then review earlier ones by typing the missing grammar into real sentences, scheduled with FSRS. Anki decks and a study timer come built in.

    New in 1.1.0

    • A kana course, and Kaeru Starter 600, a built-in deck of the 600 most useful words
    • A placement quiz that finds where you are on the grammar lines
    • Drawn profile avatars, today-only new-card limits, a smoother typing screen and iOS 27 support

    // Typing the particle as it is pronounced gives the wrong kana.
const TRAPS: Record<string, string> = { わ: 'は', え: 'へ', お: 'を' };

export function checkAnswer(input: string, example): CheckResult {
  const answer = normalizeAnswer(input);
  if (!answer) return { kind: 'empty' };

  const accepted = new Map(
    example.accepted_answers.map((a) => [normalizeAnswer(a), a])
  );
  if (accepted.has(answer)) return { kind: 'correct' };

  const alt = (example.valid_alternatives ?? [])
    .find((a) => normalizeAnswer(a.answer) === answer);
  if (alt) return { kind: 'alternative', note: alt.note };

  if (/[a-z]/.test(answer)) return { kind: 'unconverted' };

  for (const variant of trapVariants(answer)) {
    const match = accepted.get(variant);
    if (match) return { kind: 'kana-trap', suggestion: match };
  }
  return { kind: 'wrong' };
}

    Federated Learning on DCP

    Training models where the data lives. Only model information moves.

    By Theo Leone · QMIND × Distributive · 2026–now

    QMIND and Distributive are building a proof-of-concept, publicly available package for running federated learning on the Distributive Compute Platform. Training data stays on the machines that hold it, and only model information moves through DCP. There are two model tracks: logistic regression and random forest.

    My part

    • Co-owning the logistic regression track: Newton-style training and FedAvg
    • Writing the track’s summary, implementation plan and test plan
    • Contributing to the shared specs, which need a reviewer from the other track
    • The team agrees on specs before any code, and records each decision as it is made
